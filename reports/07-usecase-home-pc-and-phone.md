# 07. ユースケース実践編: 自宅PC × 外出スマホを FIPS で繋ぐ

> 「自宅のPCと外出先のスマホを繋げたい」— ごく一般的な要求を、
> FIPS(nostr-vpn)はどう解決するか。セットアップ・到達原理・
> できることの目録・限界まで。

## 0. 結論先取り

**解決できる。** しかもこの用途は FIPS の設計が最も素直に効く場面の一つ。
実際には FIPS ライブラリを直接使うのではなく、その上の製品
**nostr-vpn**(`nvpn` CLI + スマホ/デスクトップアプリ)を使うのが現実解。
やることは Tailscale とほぼ同じで、**コーディネーションサーバと
公開エンドポイントが不要**なのが違い。

## 1. どういう接続が成立するか

```
外出先スマホ (npub_A)                    自宅PC (npub_B)
   │                                      │
   ├─ 1. Nostr リレー経由で advert/シグナリング交換 (kind 37195/21059)
   │                                      │
   ├─ 2a. UDP ホールパンチ成功 → 直結      │
   ├────── 双方向 NAT 越え ────────────────┤
   │                                      │
   └─ 2b. 失敗時は FIPS メッシュの他ノードを中継経路に使う
                                          │
   = 結果: 双方に fd00::/8 のメッシュ IPv6 と npub が見える
     (FMP ホップ毎 + FSP 端末間の二重暗号は常に有効)
```

- **自宅PCは NAT の内側でよい**。グローバルIP・ポート開放・DDNS・
  VPNサーバ構築のいずれも不要。これが既存手段(自前 WireGuard、
  ポート転送+DDNS)に対する最大の違い。
- **Nostr リレーは「出会いの場」にすぎない**。advert(どの npub が
  どのトランスポートで待っているか)とホールパンチの合図を運ぶだけで、
  実データは流れない。リレーが落ちても確立済みのリンクは維持される。
- どちらかが完全に到達不能(対称NATの組合せで直結失敗)でも、メッシュ内の
  第三者ノードを経由したルーティングで届く — これが単なる P2P VPN と
  「メッシュ」の違い。

## 2. セットアップ(nostr-vpn の実際)

```bash
# 自宅PC
cargo install nvpn      # または配布済み CLI/アプリ
nvpn init               # → nostr_pubkey が発行される
nvpn set --device <そのDEVICE_ID>
nvpn start --daemon --connect
sudo nvpn service install   # 起動時自動起動(常時到達させたいなら必須)
```

```text
スマホ側 (iOS App Store / Android APK / Zapstore の Nostr VPN アプリ)
1. アプリを入れて daemon 起動 → 自分の nostr_pubkey ができる
2. アプリで join-request を生成(署名付き参加要求)
3. 自宅PC側の管理者アプリ/CLIで要求を承認 → 署名済みロースターに登録
4. 以後は自動でピア探索・直結/中継が構成される
```

要するに「Tailscale のログイン+管理コンソール」が「join-request の
Nostr 署名承認」に置き換わった形。アカウント・会社・ドメインは要らない。

## 3. 繋がったあと何ができるか

### リモートアクセス系
- **SSH / RDP / VNC / ファイル共有**: `ssh user@<PCのメッシュIPv6>` や
  MagicDNS 名で自宅PCに入る。既存ソフトはすべて無改造(IPv6 shim で
  npub→`fd00::/8` が透過的に見える)
- **自宅のセルフホストサービス**: NAS、Plex/Jellyfin、Home Assistant、
  Nextcloud、家のプリンタ、自宅 Git サーバ等に外出先からそのままアクセス

### 出口ノード系
- **自宅を「私用の出口ノード」にする**: スマホの全通信を自宅PC経由で
  インターネットに出せる。公衆Wi-Fiでも自宅の固定回線IPから出る形になり、
  見かけの位置情報・IP 制限も自宅基準になる(Tailscale の exit node と同型)。
  nostr-vpn には subnet routes / exit nodes / WireGuard 上流 egress が内蔵
- **有料出口マーケット**: 必要なら他人の出口ノードを Cashu(Bitcoin ecash)
  でバイト課金利用する実験機能もあるが、自宅PC用途では不要

### 同期・自動化系
- **Syncthing 等をこの上で走らせる**: スマホ↔PC のファイル同期を
  直接・暗号化・中継サーバ無しで実行
- **バックアップ/rsync/restic**: 外出中でも自宅ストレージにバックアップ
- **モバイルからの git push/pull、監視・ログ確認** など開発用途

### できるようになることの本質
「自宅PCの npub さえ知っていれば、世界中どこからでも・どんな NAT の
向こうからでも、その鍵に向けて IPv6 で届く」という、**ポート開放無しの
ホームサーバ化**が実現する。これは「家の中に自分専用の Tailscale を
持つ」のに等しい。

## 4. 限界と注意点(正直なところ)

| 制約 | 内容 |
|------|------|
| PC の常時稼働が前提 | Wake-on-LAN/スリープ復帰はプロトコルに無い。自宅PCを常時起動 or 別途 WoL 対策が要る |
| 帯域は自宅上りに支配 | 出口ノード用途は自宅回線のアップロードが上限。映像転送等は品質が自宅回線依存 |
| 直結が失敗するケース | 対称NAT同士等でホールパンチ不成立のときはメッシュ中継に落ちる → レイテンシ増。Nostr リレーが両者とも見えない環境(完全オフライン)では初回接続は成立しない |
| スマホ側の常時接続 | iOS/Android のバックグラウンド制約は OS 次第。アプリ側のモバイル最適化が実用性を左右する |
| 成熟度 | nostr-vpn は出荷実績あるが、FIPS 自体は監査なし・0.x。重要インフラの唯一経路にするのは早い |
| 鍵管理 | npub が全ての鍵。自宅PCの秘密鍵を失うと「住所」ごと変わる(スマホ側の許可リスト再承認が必要) |

## 5. 既存の代替手段との比較 — この用途ではどう違うか

| 手段 | 中央サーバ | 公開IP/穴あけ | 構築難度 | FIPS/nostr-vpn との差 |
|------|:---:|:---:|:---:|---------------------|
| Tailscale | 要(coord server) | 不要 | 低 | 同じUXだが会社依存。FIPSはそれを除去 |
| ZeroTier | 要(roots) | 不要 | 低 | 同上。FIPSは自己組織化 |
| 自前 WireGuard | 不要 | **自宅側に要** | 中 | FIPSは公開エンドポイント不要 |
| ポート開放+DDNS | 不要 | **要** | 中 | 穴あけ不可な環境では不可能 |
| TeamViewer/RustDesk | 要 | 不要 | 低 | FIPSは任意アプリが使える網そのもの |
| Yggdrasil 自営 | 不要(公開ピア推奨) | 一部要 | 高 | 同思想だがスマホ/ブラウザ・Nostr連携・製品UXでFIPS優位 |
| SSH トンネル単品 | 要(到達点) | 要 | 中 | FIPSは双方向任意サービス |

## 6. まとめ

「自宅PC × 外出スマホ」は **FIPS(nostr-vpn)で最も手軽に実現できる
旗艦ユースケース**であり、しかも商用メッシュVPNと同等のUXを、
中央集権なしに得られる数少ない実装。やることは

1. PC に `nvpn` デーモンを常駐化
2. スマホに nostr-vpn アプリ → join-request → 管理者承認
3. メッシュ IPv6/MagicDNS でいつものアプリを使う

の3ステップで完結する。「家の中のプライベート網を、持ち出して使う」
という要求には、現状これ以上に素直な脱集中実装はない。
